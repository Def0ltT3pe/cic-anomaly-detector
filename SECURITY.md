# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| 2.0.x | да |
| 1.0.x | только критичные исправления |
| < 1.0 | нет |

## Reporting a vulnerability

Используйте приватный security advisory в GitHub:
**Security → Advisories → Report a vulnerability**. Если это недоступно —
создайте issue без деталей эксплуатации и попросите приватный канал.

Укажите версию, шаги воспроизведения и влияние. Не публикуйте рабочий
эксплойт до исправления. Ответ — в течение 7 дней.

## Секреты

- Ключ Gemini хранится только в переменной `GEMINI_API_KEY` или
  `.streamlit/secrets.toml`. В репозитории и Docker-образе ключей быть не
  должно.
- Если ключ попал в git — **отзовите его** в Google AI Studio. Удаление
  файла не помогает: ключ остаётся в истории.
- `keys/model_signing_key.pem` — приватный ключ Ed25519. Не коммитьте и не
  передавайте его; в `.gitignore` и `.dockerignore` он исключён. Публичный
  `trust/model_public_key.pem` можно распространять.
- `.env`, `config/users.json`, `audit/` не коммитятся.

## Модели

Модели — pickle-файлы: `joblib.load` выполняет код. Держите каталог `models/`
доступным только на чтение и не принимайте его извне. При загрузке
проверяются SHA-256 и Ed25519-подпись `checksums.json`; подмена файла,
хэша, удаление подписи или самого `checksums.json` блокируются. В
Docker-образе код и модели процессу приложения доступны только на чтение.

После изменения моделей:

```bash
python make_checksums.py
```

Если ключ утерян — сгенерируйте новую пару, замените публичный ключ в
`trust/` и подпишите модели заново.

## Аутентификация и аудит

- Пароли — PBKDF2-HMAC-SHA256, 600 000 итераций, соль 16 байт.
- Роли: `admin`, `analyst`, `viewer`.
- После 5 неудачных попыток подряд логин блокируется на 60 секунд для всех
  сессий (счётчик в памяти процесса).
- События пишутся в `audit/audit.jsonl`; пароли/токены вырезаются.
- Без `users.json` и `APP_PASSWORD` локальный запуск работает в открытом
  режиме `anonymous/admin`. В Docker он выключен (`ALLOW_OPEN_MODE=0`);
  для публичного сервера не включайте его.

## Серверы сбора (вкладка «Серверы»)

- Только роль `admin` и только при локальном запуске (в Docker нет `ssh`):
  вкладка запускает на серверах команды от root.
- Пароль сервера используется один раз для записи ключа в `authorized_keys`,
  не сохраняется и не попадает в аудит; дальше — вход только по ключу.
- Ключ хоста: первый вход принимает его и пишет в `known_hosts`, смена
  ключа у известного сервера блокирует вход.
- Значения формы проверяются по белым спискам и передаются в команды через
  `shlex.quote`; адрес и пользователь не могут стать опцией `ssh`.

## Развёртывание

- Задайте `APP_PASSWORD` или пользователей.
- Порт по умолчанию публикуется на `127.0.0.1`; для доступа по сети
  используйте reverse proxy с TLS.
- Не включайте `ALLOW_UNSIGNED_MODELS=1` и не отключайте
  `VERIFY_MODEL_CHECKSUMS` без причины.
- Для LLM: в запрос уходят признаки потока и решения моделей, адреса
  маскируются. Передавайте только то, что допустимо отправлять выбранному
  провайдеру; для конфиденциального трафика используйте локальную модель
  (Ollama, LM Studio) или не настраивайте ИИ.
- `pull_captures.ps1` принимает от сервера только пути внутри своей папки
  и только файлы сбора (`capture_*.pcapng`, `ssh_*.log`, `session.json`).

## Известные ограничения

- Нет MFA/SSO и централизованной БД пользователей.
- Нет ротации `audit.jsonl` (используйте logrotate).
- Подпись Ed25519 — на хосте, не HSM.
- Блокировка входа привязана к логину (не к IP) и сбрасывается при
  перезапуске процесса.
- BruteForce-модель обучена на CICIDS и требует переобучения под сеть.
